What this course is

A six-week, fully online introduction that turns the question

“How do investors actually compute things?”

into runnable R code.

Each week we

  • start with a real investor question,
  • write down the relevant formula,
  • turn the formula into R code,
  • and visualize the answer with real market data.

Why R for finance?

  • Free and open source — no licensing barrier for students or replication.
  • A dominant language in empirical finance research alongside Python and Stata.
  • tidyverse makes data wrangling readable.
  • tidyquant wraps Yahoo Finance into one-line downloads.
  • highcharter / ggplot2 produce publication-grade charts.

1. Setting Up R and RStudio

Installation

Two pieces of software — both free:

  • R itself: https://www.r-project.org

  • RStudio Desktop: https://posit.co/downloads

Install R first, then RStudio. RStudio is the IDE you’ll actually look at.

A quick tour of RStudio

When you open RStudio for the first time, you’ll see four panes:

  • Source (top-left) — where you write and save your .R or .qmd scripts. Run a line with Ctrl/Cmd + Enter.
  • Console (bottom-left) — where R runs commands and prints results. You can also type here interactively.
  • Environment (top-right) — lists every variable, data frame, and function currently in memory.
  • Files / Plots / Help (bottom-right) — file browser, plot output, and the all-important ?function_name help pages.

Pro tip: create a new project (File → New Project) for this course. RStudio remembers your working directory and open files per project — much less painful than chasing file paths.

Installing the packages we will need

install.packages("tidyquant")
install.packages("tidyverse")
install.packages("highcharter")
install.packages("ggplot2")
install.packages("ggthemes")

Load them once per session:

2. R Syntax in Five Minutes

Arithmetic and assignment

x <- 10
y <- 5

x + y       # 15
[1] 15
x - y       # 5
[1] 5
x * y       # 50
[1] 50
x / y       # 2
[1] 2
x ^ y       # 100000
[1] 1e+05

<- is the assignment operator. = works too, but <- is conventional.

Core data types

num_var    <- 42                              # numeric
char_var   <- "Hello, R!"                     # character
bool_var   <- TRUE                            # logical
factor_var <- factor(c("low","med","high"))   # factor

Use class(x) to ask R what type a variable is.

class(num_var)
[1] "numeric"
class(char_var)
[1] "character"
class(bool_var)
[1] "logical"
class(factor_var)
[1] "factor"

Reading R’s error messages

R’s errors look intimidating but follow a pattern. The three you’ll meet most often:

1. Typo in a variable name

print(num_vra)
#> Error: object 'num_vra' not found

\(\Rightarrow\) Check spelling. R is case-sensitive: Apple \(\neq\) apple.

2. Forgotten quotes around a string

char_var <- Hello, R!
#> Error: unexpected ',' in "char_var <- Hello,"

\(\Rightarrow\) Strings need quotes: "Hello, R!".

3. Mismatched parentheses or braces

mean(c(1, 2, 3)
#> +

\(\Rightarrow\) The + prompt means R is waiting for you to close a bracket. Press Esc and check.

Habit to build: when stuck, read the error from bottom to top. The last line usually says exactly what went wrong.

3. Data Structures

Vectors and matrices

prices <- c(100, 102, 105, 107, 110)   # vector
prices
[1] 100 102 105 107 110
matrix(1:9, nrow = 3)                  # matrix
     [,1] [,2] [,3]
[1,]    1    4    7
[2,]    2    5    8
[3,]    3    6    9

A vector holds many values of the same type. A matrix is a 2-D vector — rows and columns of one type.

Data frames — the workhorse of finance

A data frame is a table: each column is a vector, each row is one observation.

stock_data <- data.frame(
  Date  = ymd("2024-01-01") + 0:4,
  Price = prices
)

This is what a downloaded stock-price table will look like.

4. The Pipe and the for Loop

The pipe |> — chaining operations

Without a pipe:

arrange(filter(mutate(data, z = x + y), z > 6), desc(z))

With a pipe:

data |>
  mutate(z = x + y) |>
  filter(z > 6) |>
  arrange(desc(z))

Read left-to-right, top-to-bottom — the way you actually think.

for loops

for (i in 1:5) print(i)
[1] 1
[1] 2
[1] 3
[1] 4
[1] 5

Looping over a price vector:

adjusted <- numeric(length(prices))
for (i in seq_along(prices)) {
  adjusted[i] <- prices[i] * 1.10
}
adjusted
[1] 110.0 112.2 115.5 117.7 121.0

We’ll use this exact pattern in Week 6 to simulate a trading strategy.

5. Pulling Real Stock Data

One line, one stock

apple <- tq_get("AAPL",
                from = "2023-01-01",
                to   = "2026-01-01")

Columns you get: symbol, date, open, high, low, close, volume, adjusted.

The adjusted column corrects for splits and dividends — this is the column we use for return calculations.

A closer look at the date column

The date column is not text — it’s a special Date class that R knows how to compare, sort, and do arithmetic on:

class(apple$date)
[1] "Date"

This lets you filter by date naturally:

apple |>
  filter(date >= "2023-07-01", date <= "2023-07-31") |>
  head(3)
# A tibble: 3 × 8
  symbol date        open  high   low close   volume adjusted
  <chr>  <date>     <dbl> <dbl> <dbl> <dbl>    <dbl>    <dbl>
1 AAPL   2023-07-03  194.  194.  192.  192. 31458200     190.
2 AAPL   2023-07-05  192.  193.  191.  191. 46920300     189.
3 AAPL   2023-07-06  190.  192.  189.  192. 45094300     189.

You can also do date arithmetic — “how many days between two dates?”:

ymd("2023-12-31") - ymd("2023-01-01")
Time difference of 364 days

Why it matters: every return, every backtest, every event study we do in this course starts with correctly-handled dates. Get this right and the rest is easy.

From daily to monthly or yearly data — (1)

A common task: collapse daily prices into monthly or yearly summaries. The recipe is always extract → group → summarise.

Extract the year and month from date with lubridate:

apple <- apple |>
  mutate(year  = year(date),
         month = month(date))
head(apple |> select(date, year, month, adjusted), 3)
# A tibble: 3 × 4
  date        year month adjusted
  <date>     <dbl> <dbl>    <dbl>
1 2023-01-03  2023     1     123.
2 2023-01-04  2023     1     124.
3 2023-01-05  2023     1     123.

Group and summarise — monthly average price and total volume:

apple_monthly <- apple |>
  group_by(year, month) |>
  summarise(avg_price    = mean(adjusted),
            total_volume = sum(volume),
            .groups = "drop")
head(apple_monthly, 3)
# A tibble: 3 × 4
   year month avg_price total_volume
  <dbl> <dbl>     <dbl>        <dbl>
1  2023     1      134.   1443652500
2  2023     2      149.   1307198900
3  2023     3      153.   1520266600

From daily to monthly or yearly data — (2)

Or roll up to annual figures:

apple_yearly <- apple |>
  group_by(year) |>
  summarise(year_open  = first(adjusted),
            year_close = last(adjusted),
            year_high  = max(high),
            year_low   = min(low),
            .groups = "drop")
head(apple_yearly, 3)
# A tibble: 3 × 5
   year year_open year_close year_high year_low
  <dbl>     <dbl>      <dbl>     <dbl>    <dbl>
1  2023      123.       190.      200.     124.
2  2024      184.       249.      260.     164.
3  2025      242.       271.      289.     169.

Tip: first() and last() (from dplyr) are perfect for “value at the start/end of the period” — the building blocks of period returns we’ll need in Week 3.

Computing a simple daily return

A first taste of what we’ll formalize in Week 3:

apple <- apple |>
  arrange(date) |>
  mutate(daily_return = adjusted / lag(adjusted) - 1)

lag() gives yesterday’s value. The formula \(R_t = P_t / P_{t-1} - 1\) becomes one line of R.

6. Visualization

The grammar of ggplot2

ggplot2 builds charts in layers, like sentences from grammar:

  • ggplot(data, aes(...)) — the subject: which data, and which columns map to which visual properties (x-axis, y-axis, color, size).

  • geom_line(), geom_point(), geom_bar()… — the verb: how to draw each row (a line? a dot? a bar?).

  • labs(), theme_*(), scale_*() — the adjectives: titles, themes, colors, axis formats.

You add layers with +. This is the only ggplot syntax you really need to remember:

ggplot(data, aes(x = ..., y = ...)) +
  geom_xxx() +
  labs(...) +
  theme_xxx()

Everything else is just looking up which geom_* you want.

A static chart with ggplot2

Code 
ggplot(apple, 
       aes(x = date, 
           open = open,
           high = high,
           low = low,
           close = close)) +
  labs(title = "AAPL Adjusted Close",
       x = "Date", y = "Price (USD)") +
  geom_candlestick(fill_up = "#0F5499", fill_down = "#DB4E60") +
  theme_minimal(base_size = 14, base_family = "Georgia") +
  theme(
    plot.background = element_rect(fill = "#FFF1E6", colour = NA),
    panel.background = element_rect(fill = "#FFF1E6", colour = NA),
    plot.title = element_text(face = "bold", size = 16)
  )

ggplot2 builds a chart layer-by-layer: data \(\rightarrow\) aesthetics \(\rightarrow\) geom \(\rightarrow\) theme.

An interactive chart with highcharter

Code 
highchart(type = "stock", width = 1280) |>
  hc_title(text = "AAPL Price and Volume") |> 
  hc_add_series(apple, 
                type = "candlestick",
                hcaes(
                  x = date,
                  open = open,
                  high = high,
                  low = low,
                  close = close
                  ),
                name = "AAPL") |>
  hc_add_series(apple, type = "column",
                hcaes(x = date, y = volume),
                name = "Volume", yAxis = 1) |>
  hc_yAxis_multiples(
    list(title = list(text = "Price")),
    list(title = list(text = "Volume"), opposite = FALSE)) |> 
  hc_tooltip(
    valuePrefix = "$",
    valueDecimals = 2,  # 2-decimal tooltips
    shared = TRUE   # show all series at once
  )

highcharter charts are interactive — pan, zoom, hover for tooltips.
